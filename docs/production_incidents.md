# 实盘事故与防再发记录

维护目标为有效执行、资金安全、稳定性、低延迟和可追溯。每次事故或高影响审核发现记录机制、处理边界及可复现验证。配置交易规则与故障恢复规则分别说明。

## 零仓阶段被提前完成

阶段已经创建、订单尚未形成仓位时，其他回调按零仓判断阶段完成，后续订单或成交失去所属阶段。阶段创建、双腿pending登记和发单前检查点形成同一提交边界，pending未确认时保留阶段。验证重复计时器、同步拒单、异步成交、开仓期间退出和空仓回退。

## LiveClock线程与到期alert

Rust LiveClock在线程池触发，直接操作策略状态会跨owner线程。计时器已经到期、回调尚在事件循环排队时，成交回调再次取消会触发NT KeyError。

`utils/live_strategy.py`提供owner绑定、跨线程投递和幂等计时器取消。ETF与SK回调核验token、状态与owner。2026-11-17真实LiveClock加sandbox复现SK异常，修复后覆盖连续四轮、暂停退出及旧alert隔离。

## Binance可用保证金字段

NT 1.230.0原生REST路径读取availableBalance，账户WebSocket把钱包余额wb写入free并把locked置零。后续WS覆盖会放大策略判断的可用资金。

`adapters/binance_account.py`独立读取原生账户。ETF与SK按策略阶段取得快照，批次内本地预留并按实际成交、费用与盈亏更新。验证模式、真实逐腿杠杆、限额、读取期间持仓变化、慢请求和失败。升级NT后重新核验映射。

## 未知订单被当作拒单

503、网络超时和UNKNOWN可能对应交易所已接受或已成交。先把NT订单变为REJECTED，再回退对冲，会导致迟到成交无法入账或重复交易。

`adapters/binance_execution.py`在模糊拒单进入NT前保留SUBMITTED。看门狗按原clientOrderId查询订单和真实成交，建立venue映射后经NT成交报告同步缓存和策略账本。核对累计成交量后确认终态，查询失败保持pending和资金预留。未决超过60秒告警，避免凭时间推断从未成交。启动遇到原订单缓存缺失保留检查点并停止启动，先人工核单。

验证真实NT报告链路、全额与部分成交、查询失败、重复trade_id、未决阶段重启、订单取消终态核对和停机期间未决订单。检查数量、费用、预留、全局批次互斥与最终净仓。

## 暂停阻断退出和重试风暴

halted检查早于exit_reason、paused提前返回，使正常回归及收盘/停机退出被挡。退出失败复用开仓失败计数，会在错误持续时自行关闭退出路径。

暂停组合保留正常回归退出及风险退出。退出失败独立计数并持续退避，减仓成交清零退出失败计数。同批双腿失败计一次。正常成功与收盘刷新交易重试，人工暂停持续保留。

## 外部等待占用执行权

等待规格或公司行动复核时继续占有executing_pair，导致无在途订单仍阻塞其他组合。执行权按实际pending和修复状态管理，外部等待归属组合自身。全局一批双腿规则覆盖未知pending。验证规格等待时另一组合可交易，全程批次重叠为零。

## 共享合约仓位归属

SKUU与SKDD共享SKHY。直接把账户净仓残差分配给某一阶段，会把另一阶段或公司行动后的数量变化归错。

订单固定所属组合，虚拟数量分别保存并与账户合计核对。共享腿存在数量差异或单位变化时保留归属进入人工复核。进程合约执行锁阻止本机ETF和SK同时控制SKHY。锁范围覆盖同模式、venue和账户类型，跨服务器单实例由部署层负责。

## NT固定停机等待

NT kernel停止trader后只等待timeout_post_stop，Strategy的market_exit还有最大次数。仍在核单或退避退出时，固定等待结束可能断开客户端。

`utils/live_node.py`先请求manage_stop策略退出，等其停止再交给NT关闭客户端和报告收尾。ETF退出检查在pending或阶段存在时持续驱动交易，全部确认平仓后才完成框架退出。重复停止请求共用同一任务。持久化和60秒未决告警继续工作，人工强制结束按检查点恢复流程处理。
