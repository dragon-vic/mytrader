# 实盘运行层重构验收

## 交付范围

活动策略为ETF套利、SK/ADR和保留的AI模块。旧回测入口、旧策略/适配器、Telegram及历史运行说明移入`legacy/`。企业微信为当前通知通道。

共享能力集中在`utils/`与`adapters/`，覆盖owner线程调度、原子检查点、运行/合约执行锁、后台原生资金读取、订单错误分类、原订单核单、通知和受管理停机。业务基线、阶段对冲比例、公司行动和交易规则保留在策略中。

## ETF执行流程

1. 取得合约执行锁与检查点锁，核对真实仓位和原订单归属，完成初始化后保存检查点。
2. 订阅17合约的L1/L5、资金费与分钟数据，建立九组合当前基线。
3. 可成交偏离达到2%，首次等待100ms复查；新阶段后台读取原生资金并核验模式、杠杆、限额和净仓。
4. 按90%可用保证金、最高10倍名义预算、每批每腿1000U、80%深度和0.1个百分点预计滑点共同缩量，预留额度并刷盘后提交双腿市价单。
5. 保留全局唯一在途批次，按真实trade_id和手续费记账。未知结果持续核单，确定失败先恢复平衡并按1秒、2秒再尝试两次，第三次失败暂停组合新增风险。
6. 每批完成时保存所有合约L1接收序号。下一笔开仓/加仓等待候选组合任一腿在完成后收到新L1，再由正常事件推进。pending期间的L1、L5、标记价和计时器各自遵循对应职责。
7. 正常退出从0.2%起按持有小时放宽到最高0.5%，每批复核。部分退出后重新越线可以再加仓。严格低于1%时重新武装100ms确认。
8. 开盘后5分钟、收盘前30分钟、资金费前后5分钟禁新增风险，收盘前5分钟开始锁定退出。
9. 退出失败独立退避，已对冲且无pending的退出等待释放执行权，裸腿恢复继续持有。暂停组合保留退出能力。
10. 系统Shutdown、Ctrl+C和策略停止请求汇入同一停止任务，策略确认退出后再断开NT客户端。

## SK故障流程

保留原业务档位与5秒轮次间隔，退出故障间隔单独配置。实际余额改为原生后台读取，完整轮次与pending清零共同持久化。确定单腿失败或同步提交异常时，核实原单后回退本轮实际成交，保留此前持仓并暂停加仓。回退期间继续判断35%全退出，触发后等待全部原/回退单明确，再按实际仓位退出。

## 核单与追溯

未知拒单在进入NT终态前拦截，按原clientOrderId查询订单与真实成交，通过NT报告链路更新缓存与策略账。累计成交量一致后确认终态。未知60秒告警，每5分钟重复。共享合约残差保留归属并进入人工复核，原订单缓存缺失的重启保留检查点并结束启动。

审计写入失败暂停新增风险，现有仓位继续退出。通知与采集均有界并与交易隔离。每次发布在运行目录保存`deployment.json`，记录提交、源码/配置SHA256和验收来源。事故机制见`production_incidents.md`，完整策略规则见`../strategies/etf_arb/OPERATIONS.md`。

## 运行约束

同机、同模式、同venue和账户类型下同一合约由一个执行进程持有，ETF/SK/AI的重叠合约适用该约束。跨机器单实例由部署流程管理。人工核单/规格复核期间保留连接和检查点，按日志中的具体订单与仓位处理后完成退出。3秒已知裸腿风险期限优先于恢复尝试次数。
