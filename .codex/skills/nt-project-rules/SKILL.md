# 项目规则

## 宗旨与验收

- 最高优先级为实盘有效性、稳定性、资金安全、策略所需低延迟和可追溯性。使用杠杆须验证放大敞口、保证金不足、单腿及部分失败。
- 框架、原生API与独立模块按实际正确性和性能选择，边界明确线程、数据契约、资源所有权与错误处理。
- 修改交易或生命周期后覆盖正常、失败、并发、重复/乱序、断连与重启，核对当前NT真实内部行为。
- 高频采集和通知使用有界缓冲、后台写入/HTTP。队列满、磁盘满、通信故障暴露缺口，保持交易线程可运行。
- 交易与错误可还原。记录代码版本、参数、时间、行情和基线、资金来源、阶段/批次/原订单号、成交ID、费用、滑点和状态变化。
- 下单前持久化pending和额度预留，明确持久化失败时的新增风险限制与退出能力。

## 验证

- 按改动风险进行临时检查，完成后清理一次性脚本，保存结果、环境、参数和证据。
- 行情与纯计算可以离线回放。线程、开仓、退出、状态保存和恢复使用真实LiveClock、NT风险/执行/持仓链路和模拟客户端，原生HTTP用隔离桩。
- 覆盖持续越线、回落再确认、零仓阶段创建、部分成交、回调重入、延迟/重复回报、未知订单、退出失败、收盘、公司行动、跨重启和共享腿。
- 低延迟链路测P99和积压，区分本机处理、网络与交易所，说明采集、组合数和负载条件。
- 模拟测试关闭真实执行和私有网络接口。实盘下单、资金操作与服务变更按当次用户授权进行。
- 按场景复测根因，验证失败修复实现和验证环境，保留实际发现。

## Git与发布

- 保留用户已有修改，按本次任务暂存。小修改默认留工作区，大改动完成充分验证后创建中文提交。
- commit、push、AWS同步、部署和重启分别处理，各自依据用户授权。
- 获得推送授权后直接推目标分支。只有用户当次要求才创建 PR。
- 生产有本地冲突先核实归属。用户授权的覆盖范围清楚时直接完成，存在归属未知的冲突时汇报具体文件。
- `.env`、凭据、真实状态和运行报告保持独立。回答与日志中保护密钥及签名URL。
- Claude审查候选快照放隔离草稿目录，审核过程与生产运行目录分开，部署和重启按当次用户授权执行。

## 本地和远程命令

- 本地 Windows 使用 PowerShell 7。
- 已授权项目操作需要网页OAuth或发布登录时，优先直接通过Chrome完成授权，使用用户已有的登录会话。仅在账号登录、验证码、MFA或浏览器工具无法完成的步骤需要用户操作时，说明具体环节并请求协助。授权范围限于当前项目所需操作，凭据按下文规则保护。
- Chrome插件的控制入口可能通过Node工具加载，工具列表中缺少独立Chrome名称时，先检查本机官方Browser模块。当前已验证路径为 `C:/Users/victor/.codex/plugins/cache/openai-bundled/browser/26.1111.21308/`，版本随应用更新，使用时核对实际目录。先读该目录 `skills/control-in-app-browser/SKILL.md`，再按其说明通过 `mcp__node_repl__js` 加载 `scripts/browser-client.mjs` 并连接Chrome；连接成功后复用已有浏览器句柄。旧标签报`Debugger unattached`时，在同一Chrome中新建标签重试并保留用户原标签。2026-11-17本项目已通过该入口成功连接Chrome并完成Cloudflare授权。插件故障按 `D:/add/codex/skills/codex-browser-repair/SKILL.md` 定位，保留账户隔离和权限检查。

- 不在未确认目标路径的情况下执行递归删除、移动或覆盖。

## 资金与执行

- 可用保证金由项目原生账户模块处理，核验交易所字段语义、更新时间、模式、杠杆、限额及在途预留。
- 已出现Binance框架REST用`availableBalance`而账户WS用钱包`wb`覆盖`free`的问题。原生可用保证金承担资金判断，阶段内以本地实际成交、费用、盈亏和预留记账。框架升级复核字段与更新链路。
- 结果未知的下单保留pending和额度，按原clientOrderId核单。使用真实成交ID、数量和手续费经NT标准报告链路记账，确认策略量与交易所累计成交一致再释放。
- 模糊拒单在适配器进入NT REJECTED前拦截。框架终态与交易所事实分别核验，超时仅查询市价订单。无订单回复或订单不存在查询继续保持未知并告警，人工核查处理。
- 只有确定性错误计入开仓交易失败。ETF恢复平衡后等待1秒和2秒各重试一次，第三次失败暂停该组合。正常批次成功和实际美股收盘刷新计数，暂停状态继续等待人工处理。
- 正常退出和强制退出保持可执行，退出失败独立1/2/5秒退避，最高5秒。暂停仅限制新增风险。减仓修复优先处理单腿多出敞口。
- 全局每次只有一批双腿订单。pending与实际敞口决定归属，等待外部规格/事件复核且无pending时释放执行权，其他组合按规则执行。
- 共享合约采用逐订单、逐阶段虚拟数量账。账户净仓用于核验，共享腿发生单位变化或数量不匹配时保留归属供复核。
- 重启遇到未决订单且缓存缺失、成交量不一致或归属冲突时，保留检查点并按停止协议结束启动，先核单恢复事实。

## 行情与生命周期

- Binance bid/ask为变更驱动数据。链路正常时最后L1持续有效，行情连接、订阅、错误状态独立检测。成交后按方向扣减尚未覆盖的容量，排除成交前的L5。
- 首次及重新越线确认遵循策略参数，部分平仓后每批重新检查信号，允许再次加仓时按实际释放额度计算。
- 策略可变状态只在owner线程操作。真实LiveClock回调先投递到事件循环，检查timer token和停止状态。到期alert已从框架删除但回调尚在队列时，取消动作按幂等处理。
- 新私有方法先核对NT基类名称与签名。回测和纯行情压测分别验证对应路径，线程和执行路径独立验收。
- 双腿提交前共同登记pending。计时器、回报与无关行情保持重入保护。零仓阶段在订单确认前保留阶段。
- 使用共享批次提交处理同步异常及同步拒单。已进NT缓存且结果未确认的订单保留核单，未尝试的后续腿停止提交。策略根据真实成交决定补齐或回退。
- 仓位先聚合signed quantity，兼容NT同一合约多position ID。新增风险检查目标金额、实际净仓、尾仓、步长、限额和额度。
- Node统一处理停止、报告与资源释放。策略通过停止协议请求Node，业务退出与人工停机按各策略规则分别处理。
- 常见网络和只读失败暂停新增风险、保留匹配对冲并退避。明确收盘/公司行动、无法修复单腿和关键状态故障触发相应风险退出。

## 架构、配置与资料

- `run.py`、`live.py`和共享模块保持策略无关，业务差异通过配置和明确接口表达。
- 策略私有代码、配置、研究、报告和状态放对应策略目录。跨策略复用能力放`utils/`或`adapters/`。
- 新增/删除入口、策略和共享模块同步更新`nt-project-context`与受影响说明，实盘事故记录到`docs/production_incidents.md`。
- YAML使用结构化类型，必需字段在配置声明，未知/缺失/类型错误尽早报错。交易所市场规则由adapter解释。
- 遗留硬编码先区分交易规则、单位、故障恢复和历史配置，再决定变更。当前有效交易规则保留业务语义。
- 废弃实现移出活动入口，归档保留研究来源。旧接口迁移完成后删除重复wrapper。
- tools默认独立调用，接入生命周期以用户授权和明确协议为依据。
- 图表交付为可独立打开的HTML或高分辨率图片，复杂多面板提供文件链接。
- 本地任务分发沿用现有入口，保持浅目录和直接实现。依赖安装按用户授权，使用项目nt环境，下载与产物优先D盘。
